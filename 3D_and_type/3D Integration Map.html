DESIGN PRINCIPLE — WHEN TO USE EACH COMPONENT
⬡
Perspective cards — only on things you enter, choose, or connect. Buildings, tier selection, archetype cards, connector cards. Never on static information displays or sidebar nav items.
◈
Extruded badges — status that matters. FY tags, tier identity, system live states, task stages. Green = active/live/go, cyan = informational, gold = premium/earned, red = warning. Never use flat text where a badge belongs. Never use a badge where flat text is sufficient.
◎
Physical toggles — binary mode switches only. Billing cycle, avatar/text mode, audio on/off, sync on/off. Not for filters, not for settings, not for anything with more than two states. The thumb sliding is a commitment — reserve it for choices that feel like one.
▣
Depth inputs — conversation and identity only. FY chat, studio naming, formation answers, subscribe commitment. Not for search, not for filters, not for utility inputs. The sunken well says: what you put here matters.
